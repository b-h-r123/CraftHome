# v0.2：从空服务器到首次开服

本轮交付范围是 Linux 安装、版本选择、新建独立服务器、首次启动。管理引擎复用 MCSManager 官方发行版，通过 HTTP API 集成；游戏运行使用 Paper 官方稳定构建。没有自行重写进程管理器或修改 Minecraft 内核。

## 1. 在新服务器安装

支持 Ubuntu 24.04 x86_64，建议至少 2 GiB 内存；512 MiB Java 堆仅用于低资源功能测试。操作账号需要 sudo 权限。服务器需要访问 GitHub、Node.js、Paper 和 Mojang 官方下载站点。

```bash
curl -fL https://raw.githubusercontent.com/b-h-r123/CraftHome/main/deploy/linux/bootstrap.sh -o bootstrap.sh
sudo bash bootstrap.sh --check
sudo bash bootstrap.sh --public
```

`--check` 只检查环境。正式安装会准备缺少的系统依赖、Java 21、固定版本的官方 Node.js 和 MCSManager，校验下载文件 SHA-256，建立 systemd 服务，并将引擎连接安全交给控制台。不会自动创建世界或接受 EULA。

默认程序目录 `/opt/crafthome`，控制台数据 `/var/lib/crafthome`，引擎 `/opt/mcsmanager`。三个服务分别为 `crafthome`、`mcsm-web`、`mcsm-daemon`。它们以独立的系统用户运行。管理端口 23333、24444 保持回环监听。

不加 `--public` 时，通过本地 SSH 隧道使用 WebUI。加该参数时打开 `http://服务器公网IP:5080`，并在云安全组允许 TCP 5080。游戏使用另一个端口；默认 25565，安装器为其添加 UFW 规则。自选端口需自行放行系统防火墙和云安全组。HTTP 登录适合当前测试，长期公网使用应增加 HTTPS。

首次账号读取：

```bash
sudo cat /var/lib/crafthome/first-login.txt
```

邮箱为 `owner@crafthome.local`，密码随机生成，不在安装日志展示。登录后修改密码。修改后该文件中的旧密码不再有效。引擎首次管理员凭据保存在 root 私有文件 `/root/crafthome-mcsmanager-admin.json`，普通服主无需读取或填写引擎 API Key。

## 2. 在网页创建

打开“新手开服”，确认本机引擎已连接，Java 至少 21。页面检查可用内存、磁盘、端口。创建和首次启动前还会再次检查；不足时拒绝操作，不会自动删除已有服务。

填写名称、Paper 1.21.x 版本、Java 堆内存、游戏端口、玩家使用的公网 IP 或域名。默认 Java 堆内存为 1024 MiB。构建号取所选版本最新的 STABLE 构建，具体版本列表来自 Paper 官方。选择版本会创建一台独立实例，使用自己的世界目录。

默认启用正版验证。允许离线账号时填写玩家名，系统开启白名单并按离线 UUID 写入。玩家名区分大小写。PCL 只是启动器，能否加入取决于游戏版本、账号模式和白名单。当前没有游戏内密码插件，离线玩家名可能被冒用。

阅读并勾选 Minecraft EULA 后点击“创建服务器”。系统先下载并校验服务端文件，再通过 MCSManager 建立独立实例、上传服务端并写配置。未确认 EULA 不会创建实例。下载哈希不符时不启动游戏。

“创建完成”仍未开服。点击“首次启动并管理”，等待首次下载依赖和生成世界。只有进程运行且游戏查询已响应，才自动进入管理页。超时或退出时看日志，避免反复新建。中途关闭页面可能留下未完成实例；向导下方可以找到已有实例，上游 MCSManager 也能检查文件。

客户端选择相同 Minecraft Java 版本，在多人游戏中填写 `公网IP:游戏端口`。WebUI 的 5080 不是游戏端口。`127.0.0.1` 只代表各自电脑，其他玩家应使用公网地址。查询成功不能证明云安全组已放行。

“已有服务器 → 切换并管理”只改变当前控制台管理对象，保留其他实例。当前列表最多显示前 50 个；多个实例同时运行会分别占用内存。

## 3. 已安装机器升级

```bash
sudo bash bootstrap.sh --upgrade
```

升级前程序备份到 `/var/backups/crafthome/program-时间.tar.gz`，保留控制台数据、账号、现有 systemd 公网配置和游戏实例。已有 MCSManager 不会自动更新或重置账号；若无可用管理员 API Key，脚本会退出并要求在原面板启用。此备份只是程序备份，不包含游戏世界备份。

当前机器已经部署完成时不必重复安装，直接进入 WebUI 的“新手开服”。

## 4. 从源码构建与本地开发

安装 .NET 10 SDK，在仓库根目录：

```powershell
dotnet test tests/CraftHome.Tests/CraftHome.Tests.csproj
dotnet publish src/CraftHome.Web/CraftHome.Web.csproj -c Release -r linux-x64 --self-contained true -o artifacts/linux-x64
tar -czf artifacts/crafthome-linux-x64.tar.gz -C artifacts/linux-x64 .
```

本机仓库在 `D:\MCstart`；若没有全局 SDK，将 `dotnet` 替换为 `.\.local\dotnet\dotnet.exe`。Linux 安装自包含包不需要 .NET SDK。源码内的 `.local`、账号库、API Key、SSH 密码和 SDK 不提交 Git。

把包和 `deploy/linux/bootstrap.sh` 传到 Linux，执行：

```bash
sudo bash bootstrap.sh /绝对路径/crafthome-linux-x64.tar.gz --public
# 已有安装则再加 --upgrade
```

Windows 开发运行 `start.ps1`，可以调试页面和管理已有实例。Linux 的本机资源检测与新建向导应在 Linux 测试。

开发验证可以运行独立的浏览器测试：

```bash
npm ci --prefix tests/browser
cd tests/browser && npx playwright install --with-deps chromium && cd ../..
export CRAFTHOME_URL=http://127.0.0.1:5080
export CRAFTHOME_LOGIN_FILE=/安全目录/first-login.txt
export CRAFTHOME_GAME_MEMORY=1024
node tests/browser/smoke.cjs
```

只对测试环境运行，该脚本会真实创建、启动、查询和停止实例。登录文件也可只含当前密码的一行；勿写进命令或提交仓库。测试报告默认在被 Git 忽略的 `reports/`。GitHub Actions 同时验证干净 Ubuntu 安装和完整浏览器流程；只有 tag 验证成功才发布 Release。

## 5. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 页面打不开 | `systemctl status crafthome`，确认监听地址、TCP 5080 防火墙和云安全组 |
| 环境检测内存不足 | 正常停止不用的实例或增加内存；不要删除世界来腾内存 |
| 官方版本下载失败 | 检查服务器到 Paper 官方下载站的网络；不替换为未校验的第三方包 |
| 创建中断 | 检查下方已有实例和日志；失败实例保留，不覆盖旧世界 |
| 进程运行但查询未响应 | 等待生成世界，查看日志中的异常或内存不足；先不要反复重启 |
| 客户端 Connection refused | 检查实例运行、实际游戏端口监听、公网 IP、防火墙与安全组 |
| 白名单拒绝 | 检查正版／离线模式、玩家名大小写和客户端版本 |

上游接口参考：[MCSManager 文件 API](https://docs.mcsmanager.com/apis/api_fileManager.html)、[Paper 下载服务](https://docs.papermc.io/misc/downloads-service/)。
