# CraftHome v0.1 基础控制版测试报告

测试日期：2026 年 10 月 27 日（北京时间）。源码位置：`D:\MCstart`。

本报告记录首次通过 SSH 隧道访问的测试快照。后续按用户要求修改了公网监听方式；当前访问方式与公网验证进度见 `公网访问说明.md`。

## 结论与交付范围

第一版已经在 Windows 本地和指定 Linux 服务器运行。已实现服主登录、已有实例连接设置、状态与内存查询、最近日志、启动、正常停止和重启。Linux 实服通过了 Minecraft 协议状态查询，浏览器能控制实际 Java 进程。

这是“连接并管理一个已有实例”的基础版本。**没有实现全自动安装管理引擎与创建游戏实例、版本切换、插件／Mod 安装、游戏内角色或区域保护。** 当前安装脚本安装 CraftHome 控制台；本次 MCSManager 和隔离游戏实例由测试部署流程准备。不能将本次结果理解为最初全部产品设想已经完成。

## 实服观察与资源边界

第一次创建独立世界并准备完成约 **106.85 秒**。后续启动约几十秒，具体受磁盘缓存和服务器资源影响。最终完整浏览器启动、重启、停服流程约 **133 秒**，Java PID 从 **100750** 变为 **100833**。这些数据不能作为性能承诺。

512 MiB 是 Java 堆上限，不是进程总内存。运行时 Java 进程内存曾约 **760 MiB**。停服后一次系统采样为：内存使用约 678 MiB、可用约 934 MiB、Swap 使用 0。该配置仅用于功能验证，**没有完成玩家人数承载、长时间稳定性或性能压测**。

测试没有真实 Minecraft 客户端登录，没有验证公网游戏端口、多人游戏、模组兼容性或世界回档恢复。游戏实例只在回环地址监听，通过 SSH 隧道进行协议查询；普通玩家目前不能直接通过服务器公网 IP 加入该测试实例。

## 原有服务和测试结束状态

用户批准后停止了原 `minecraft.service`。日志确认原世界各维度均保存完成。旧启动脚本随后以 **130** 退出，systemd 将其记录为 `failed / exit-code`；这是旧服务的退出记录，不能据此说旧 unit 获得了成功退出状态。未编辑旧 unit 或启动脚本；原世界和插件保留，游戏退出时进行了正常存盘。

测试结束时：

- `crafthome.service`、`mcsm-web.service`、`mcsm-daemon.service` 保持运行。
- 新隔离游戏实例已正常停止，关闭自动启动／崩溃自动重启。
- 原游戏进程已停止；原 `minecraft.service` **仍保留开机自启设置**，重启机器后可能再次启动。
- 本次不需要删除服务或原有数据来腾出空间，未执行此类删除。

需要恢复原服时，先确认测试实例停止，再在服务器执行：

```bash
sudo systemctl reset-failed minecraft.service
sudo systemctl start minecraft.service
sudo systemctl status minecraft.service --no-pager
```

恢复命令未在本次测试末尾执行，以免重新占用资源。原服恢复后的游戏行为不在本次验证范围内。

## 目录与访问方法

| 内容 | 服务器路径 |
| --- | --- |
| CraftHome 程序 | `/opt/crafthome` |
| CraftHome 数据与密钥 | `/var/lib/crafthome` |
| MCSManager | `/opt/mcsmanager` |
| 独立测试世界与游戏文件 | `/opt/crafthome-test/game` |
| 原 Minecraft 文件 | `/opt/minecraft` |

当前电脑上的远程控制台入口为 `http://127.0.0.1:5081`，依赖 SSH 隧道。隧道关闭后，在 `D:\MCstart` 打开 PowerShell，执行：

```powershell
.\scripts\connect-server.ps1 -Server 47.104.68.190 -User root
```

若提示本地 5081 被占用，说明已有隧道或其他进程占用；先确认现有连接，或用脚本的 `-LocalPort 5082` 参数改端口，再访问相应地址。

远程控制台登录邮箱为 `owner@crafthome.local`。其初始密码保存在本机 `D:\MCstart\.local\server-first-login.txt`，服务器原始文件为 `/var/lib/crafthome/first-login.txt`。本报告不包含密码和 API Key。Windows 本地演示控制台使用另一份 `src/CraftHome.Web/.local/first-login.txt`，两份凭据不能混用。

源码内的 `.local`、编译目录和发行包已排除 Git；发行文件清单不包含数据库、首次密码、连接配置或运行密钥。

## 本次修正与后续工作

已修正交互连接建立前按钮可能被误点的问题、未开放账户路由的校验顺序、账户页重复布局，以及终端日志中的控制字符显示。修改密码测试曾因成功提示的标点断言错误而中断；测试账户经备份后恢复，修正脚本后完整改密／恢复／退出／登录流程通过，最终初始密码仍有效。

上游自动安装脚本的下载过程在本次环境受阻，因此部署改用同一官方固定发行包和标准 systemd 配置，没有跳过证书校验。这个结果不等于跨发行版的一键安装器已经验证完成。

下一阶段建议优先完成：安装环境检测、实例创建向导、EULA 确认、端口冲突检查、内存预算与首次备份；通过这些步骤后，再实现插件／Mod 和权限／领地管理。当前仅验证 Ubuntu x86_64 部署；Windows 本地控制台可运行，ARM、其他 Linux 发行版和 Windows 游戏引擎部署尚未测试。

复现构建、启动和自动测试的方法见仓库 `README.md`。本项目尚未推送到 GitHub。
